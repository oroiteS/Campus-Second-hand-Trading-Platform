## 三、修复过程中引入并闭环的回归

**空游标判真 → 流水/画像全不写 + 熔断全开。**

- **现象**：行为写入路径改写后，`_record` 的异常兜底与 `_write_behavior` 拆分把「无去重命中」的哨兵值当成了真值判断，导致去重分支恒命中：行为流水不写、画像不更新；同时每次写入被判失败，连续失败计数迅速达阈值，熔断常开——表现为「详情点击无画像、推荐永远冷启动」。
- **发现**：第 1 轮独立验证（对照真实 Mongo 落库结果与 `user_behaviors` 文档数）。
- **修复与闭环**：第 2 轮修复 `behavior_service.py` 去重判定（显式 `dedup_hit = False` 初值 + 分支赋值，不使用游标真值），并按「桩改造后先红后绿」流程隔离验证——先让桩暴露该语义（用例转红），再改实现（用例转绿），避免同类假绿复现。
- **守护测试**：`tests/test_behavior_service.py::TestRecordView`、`TestRecordFavorite`、`TestFavoriteDedupDirection`、`TestMongoCircuitBreaker`。

## 五、刻意不改（含理由）

| # | 项 | 理由 |
| --- | --- | --- |
| 1 | `mine?status=deleted` 可查出已删商品（S-9） | `deleted` 是契约 `ProductStatus` 的合法枚举；查询恒带 `seller_id = 本人`，返回的是本人数据，不构成越权或信息泄露。改拒绝该值反而与契约枚举冲突，故仅补口径注释。 |
| 2 | `unfavorite` 对 `status=deleted` 返 404 造成的孤儿收藏行（S-10） | 列表侧 join 已排除 `deleted`，孤儿行不展示、无容量与一致性问题；专门清理属 YAGNI，转 b5 商品处置/清理任务一并处理。 |
| 3 | `degraded_reason` 之外的历史文案 | 本轮只把「会带内部信息/口径漂移」的文案收敛到 `services/degradation.py`；其余既有对客文案（错误码表、状态标签等）不在审查项内，避免无收益的批量改动。 |
| 4 | mock SVG 商品封面版式与真实图片不一致 | mock 只服务离线演示，封面仅需可辨识；为对齐版式重写 SVG 成本高于收益，且会掩盖真实图片的 `object-fit` 差异，故不复用真实版式。 |
| 5 | `tools/local_embedding` 的临时改动 | 属审查期临时调整，**已还原**至仓库基线（见 `git status`：`tools/**` 无改动），不进入本批提交。 |
| 6 | D-1（列表/搜索 `campus_id` 筛选）、CORS、b5 分类管理 | 属后续批次范围（b3/b5 任务卡），与本次回溯修复的阻断/建议无耦合，按原计划分批推进，避免跨批次扩大改动面。 |
