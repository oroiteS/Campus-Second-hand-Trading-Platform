**阻断 4 项 / 建议 12 项。**

## 四、问题明细

### 阻断

#### B-1【前端】取数 hook 从不重入加载态 → 搜索/筛选期间显示假空态

- 位置：`campus_frontend/src/hooks/useQueryList.ts:25-58`；消费处 `pages/product/SearchPage.tsx:127,177-186`、`pages/product/ProductListPage.tsx:150,206-212`、`components/StateView.tsx:26-53`
- 现象：`loading` 初值 = `enabled`（`:28`），此后**只有 settle 时** `loading:false`（`:41,47`）；effect 内无 `setLoading(true)`（`:33-52`），`retry()` 只递增 tick（`:54-56`）不清 error。搜索页初始 `enabled=false`（q 为空）→ `loading=false`、`data=null`；用户提交后 `enabled` 翻真、`data` 仍 null → 页面按 `empty={(data?.items.length ?? 0) === 0}` 判定为空，**在请求飞行期间渲染「没有找到相关商品，换个关键词或放宽筛选试试」**，随后结果替换；列表页筛选变更同因无加载指示，上次 0 条时继续显示「没有符合筛选条件的在售商品」。
- 判定依据：`frontend/02-商品界面.md:66` 要求「加载/空/错误可重试三态」；`frontend/00-骨架与契约` 四态基线；规范 v0.7 阻断定义「能导致错误…一律计阻断」。空态文案是**与事实相反的结论**，且出现路径是站内搜索主路径（导航进 `/search` → 输入 → 提交），非边角。
- 修复方向（约 1 处）：`useQueryList` 在 effect 进入时 `setState(prev => ({...prev, loading: prev.data === null}))` 或暴露 `fetching` 由页面加 `aria-busy`/骨架；`retry()` 同时清 error。补一条「enabled 由 false→true 时先渲染骨架」的复现用例（b3 起前端有 vitest 缺口，可先用人工走查登记）。

#### B-2【后端·向量】混维旧画像被静默写入，`dim` 字段谎报，用户推荐永久降级

- 位置：`src/services/behavior_service.py:100-121`（`zip(product_vector, old, strict=False)`、`dim` 固定写 `EMBEDDING_DIM`）；放大因素 `vector_service.rebuild_all():196-219` 只重建 `product_vectors` 与 Chroma，**不清 `user_profiles`**
- 现象（实测）：给 `user_profiles` 预置 768 维旧画像（`dim:768`）后触发一次详情点击，落库结果为 `vector` 长度 **768**、`dim` 字段 **1024**、`behavior_count` 递增；随后 `GET /recommendations/home?refresh=true` 返回
  `degraded: true / 画像召回异常…InvalidArgumentError: Collection expecting embedding with dimension of 1024, got 768`。
- 判定依据：任务卡 `backend/02-向量与推荐.md:48`「维度不符 → 拒写 + error 日志（切模型须重建，不得混维）」、验收条 `:105`；需求「切模型须重建，不得混维」。当前实现只校验**商品侧**向量维度（`behavior_service.py:75-78`），不校验**存量画像**维度，且 `zip(strict=False)` 把"维度不一致"退化成"静默截断"。
- 影响：换 Embedding 模型（含维度变化）后，所有老用户第一次行为即写入混维画像，推荐**永久**走 degraded 全随机——正好踩中"纯随机冒充推荐"反目标的观感面；数据已污染且无自愈入口（`rebuild_all` 不清画像）。
- 修复方向：混合前显式断言 `len(old) == len(product_vector) == EMBEDDING_DIM`；不符则丢弃旧画像（`new = product_vector`）、`behavior_count` 归 1、error 日志；`rebuild_all` 增加可选 `--reset-profiles` 或文档明确"换模型须手动清 `user_profiles`"；补一条 768 维旧画像用例。

#### B-3【后端·向量】删除补偿路径把龄期重置，24h 死信上限失效 + `replayed` 虚高

- 位置：`src/services/vector_retry_worker.py:60-66`；`src/services/vector_service.py:185-193,85-91`
- 现象（实测）：向队列投一条 `ts` 为 25 小时前的消息（`product_id` 不存在），令 Chroma 端口不可达后执行 `process_once`：返回 `{"replayed":1,"dropped":0,"failed":0}`，消息**回队且 `ts` 变为当前时间**（原 `1792678194` → 新 `1792768194`）。
- 机理：删除分支调用 `remove_product()`，其内部 `except → _enqueue_retry()` 用 `int(time.time())` 重新生成 `ts`，异常被吞；worker 无条件 `replayed += 1`，既不计失败也不判龄期。
- 判定依据：任务卡 `backend/02-向量与推荐.md:63`「单条重试失败且超 24h 丢弃 + error 日志防死信堆积」；同一文件 docstring 自述「保留原 ts——龄期不因重放重置」。该承诺在正常分支成立，在删除分支被绕过。
- 影响：Chroma 长时间不可用 + 期间有删除动作时，同一 `product_id` 每 60s 被无意义重排一次、永不过期，死信防护形同虚设；运维从日志看到的是"重放成功"的假象。
- 修复方向：给 `remove_product` 加 `strict=True`（抛出让 worker 按原 `ts` 判龄期），或 worker 侧先判龄期再调用；`replayed` 只在真正成功时 +1。

#### B-4【安全·跨批次】明文 Mongo 凭据入仓

- 位置：`campus_backend/src/config.py:134-137`（`MONGO_URI` 默认值）、`campus_backend/.env.example:27`（入 git 的模板，同一串）；来源 `git blame` → `af411077`（2026-10-20，b0 骨架），非 b2 引入
- 现象：`mongodb://***:***@<host>:<port>/<db>`（**本报告已脱敏**：账号口令与公网 IP 不在正文复述，原串见 git 历史 / b0 提交 `af411077` 的 `config.py:134-137` 与 `.env.example:27`），账号密码与远端主机均为真实值；模板注释还声称"认证走 authSource=admin"而 URI 里并无该参数，语义自相矛盾。
- 判定依据：需求 NFR-13「全部外部依赖地址与密钥通过环境变量注入，**仓库不含明文密钥**」；规范「配置管理」节（模板入 git、真实凭据只进 `.env`）。v0.7 发布审查清单第 4 条「安全」。
- 影响：任何克隆仓库者都拿到该远端库读写凭据；未配置 `.env` 的部署会把全部向量/行为/画像写到外部主机。
- 修复方向：默认值改空串或 `mongodb://127.0.0.1:27017/campus_market`，缺失即启动报错；`.env.example` 换 `change_me` 占位并补 `authSource` 说明；**若该凭据真实有效，应视为已泄露并轮换**；顺带评估是否从 git 历史清除（成本高，至少轮换）。
