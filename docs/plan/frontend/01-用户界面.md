## 📁 交付物清单（精确文件）

### 1. api 层四模块 + mock 四件

| 文件 | 导出函数（消费生成类型，签名随 0.2.0） |
| --- | --- |
| `api/auth.ts` | `register(body: RegisterInput): Promise<UserProfile>`、`login(body: LoginInput): Promise<LoginData>`、`logout(): Promise<void>`、`resetPassword(body: PasswordResetInput): Promise<void>` |
| `api/users.ts` | `getMe(): Promise<UserProfile>`、`updateMe(body: ProfileUpdateInput): Promise<UserProfile>`、`changePassword(body: PasswordChangeInput): Promise<void>`、`uploadAvatar(file: File): Promise<UserProfile>`（FormData） |
| `api/certification.ts` | `submitApplication(form: {school_id; campus_id?; real_name; student_no; file}): Promise<AuthApplication>`（multipart）、`getMyApplications(): Promise<AuthApplication[]>` |
| `api/schools.ts` | `listSchools(): Promise<SchoolWithCampuses[]>` |

- `api/mock/` 下 `auth.ts` `users.ts` `certification.ts` `schools.ts` 与上表一一对应，数据结构**逐字段同构**契约 schema，经 `utils/delay.ts` 模拟延迟；mock 中的 `UserProfile.phone` 一律给合法形态（`13812345678`）或 `null`，不得出现非法示例误导联调；mock 场景须覆盖：登录成功（三种账号：未认证/已认证/管理员）、2005、1006、注册 9001 字段错误（含 `phone` 非法样例）、驳回申请（含 reject_reason）供状态页演示。
- 沿用 b0 模式：每函数内部 `USE_MOCK` 分流；页面禁止直接 fetch/axios。

### 2. `stores/authStore.ts` 接真实流程

- `user` 类型 `UserSummary` → `UserProfile`（`types/` 同步 re-export）；`phaseOf` 派生逻辑不变（role/auth_status 判定，不本地推测）。
- **移除** `setDemoPhase` 与 `DEMO_USERS` 依赖；连带删除 `components/AuthDemoSwitcher.tsx` + `.css` 及全部引用（b0 演示遗留物，批次计划决策点 6）。mock 模式下四态验证改由 mock 登录数据承担。
- persist 键 `campus-auth` 不变；`clearAuth` 后由统一 401 处理引导跳转（下条）。

### 3. `api/http.ts` 401 统一引导（b0 留痕建议项落地）

- 1001/1002/1003 现有"清令牌"基础上追加：**当前路由非游客页时** `window.location.assign('/login')`（避免登录页循环跳转）；1004 保留语义位（商品域 b2 启用，本批次不出现在用户域接口）。

### 4. 页面五张（`pages/`，沿用现有占位文件原地完善）

| 页面 | 功能与状态要求 |
| --- | --- |
| `auth/LoginPage.tsx` | `account` + `password` 表单；成功 → `setAuth(access_token, user)` → 按 `from` 参数或角色回首页；`2005` 表单级错误、`1006` 限流提示（含剩余时间语感）、`2006` 封禁提示，均 `role="alert"` 可见反馈 |
| `auth/RegisterPage.tsx` | 五字段；客户端预检按批次计划「**3.0 字段校验对照表**」逐项实现（用户名 `^[A-Za-z][A-Za-z0-9_]{0,31}$`、密码 `^(?=.*[A-Za-z])(?=.*\d).{8,64}$`），预检不替代后端复验；`9001` 的 `data.fields` 逐字段内联展示（`aria-invalid` + `aria-describedby`）；`2001`/`2002` 提示；成功回填账号并跳登录 |
| `auth/ForgotPasswordPage.tsx` | 渠道切换（学号/邮箱）+ `reset_value` + 新密码（预检同对照表）；`2004` 提示不泄露存在性（文案统一"校验未通过"）；成功跳登录 |
| `account/ProfilePage.tsx` | 资料卡（展示名/学校/校区/认证徽章/头像）+ 编辑（nickname/email/phone，仅提交变更字段；**`phone` 预检 `^1\d{10}$`（1 开头 11 位纯数字），非法即表单内联报错不发请求，清空输入框 = 空串清除**）+ 改密弹窗（`2003` 原密码错误内联到该字段；新密码预检同对照表）+ 头像上传（客户端预检类型/5MB、本地预览、`aria-label`）；未认证用户同样可达（`RequireAuth` 已覆盖） |
| `account/CertificationPage.tsx` | 学校下拉（`listSchools`）→ 校区级联（`multi_campus` 必选、单校区隐藏）；`student_no` **预填注册值且只读**（防代认证，与后端校验呼应）；`real_name` + 学生证照片上传（预览 + "示例材料"提示）；状态区：`unverified` 显示表单、`pending` 显示审核中（禁止重复提交）、`rejected` 显示 `reject_reason` + 重提按钮、`approved` 显示完成态；历史申请列表（时间倒序，状态徽章） |

- 通用要求：每页四态齐备（加载 `aria-busy`/空/错误可重试/正常）；触控目标 ≥ 44px；320px 起可用；色值间距全部取 `tokens.css`/antd 主题，零硬编码；路由级 lazy 已由 b0 路由表承担，新增页面不破坏分割。

1. **错误码反馈完备性**：`1002` 清令牌并引导、`1006`/`2005`/`2006`/`2001`–`2004`/`9001`(fields)/`9003` 每个码都有用户可见文案，无静默吞错。

6. **校验同源**：三张表单的预检规则与批次计划「3.0 字段校验对照表」逐项一致（重点 `phone` 11 位、`password` 字母+数字），且非法输入被预检拦截后**不发出请求**；后端 9001 返回时内联展示而非整体 toast 了事。
