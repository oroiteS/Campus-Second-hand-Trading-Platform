## 🎯 目标与范围

在 b1 骨架上实现契约 0.3.0 的**商品核心 12 个接口**，落地 `scoped_query` 查询改写、商品缓存、图片 Cookie 通道与事件总线（向量订阅留给 b2be2），并完成 b1 存量三处微改。

**做**：4 表迁移、商品 CRUD/状态/删除/我的商品、图片上传与孤儿清理、收藏三接口、分类列表、在售列表筛选、`scoped_query`、detail/category 缓存、事件总线与 6 事件点、图片 Cookie 通道（login/logout/images）、405 全局错误。
**不做**：向量搜索 `GET /products/search` 与推荐 `GET /recommendations/home`（b2be2）、向量/画像/行为的真实订阅逻辑（本任务事件 no-op）、分类管理 CRUD（b5）、订单与 `trading/sold` 流入边（b3）、敏感词匹配逻辑（钩子 no-op，词库 b5）。

| 契约接口 | 归属 |
| --- | --- |
| `GET/POST /api/products`、`GET/PUT/DELETE /api/products/{id}`、`PATCH /api/products/{id}/status`、`GET /api/products/mine` | b2be |
| `POST/DELETE /api/products/{id}/favorite`、`GET /api/favorites/mine` | b2be |
| `GET /api/categories`、`POST /api/uploads` | b2be |
| `GET /api/products/search`、`GET /api/recommendations/home` | **b2be2**（本任务不建路由文件） |

## 🔗 Interfaces（b2be → b2be2 的接力契约，双卡共同引用）

b2be2 的全部工作建立在本节之上；**签名不得偏离**（发现缺陷停手上报，走计划修订）：

1. **事件总线** `src/services/events.py`：

```python
_HANDLERS: dict[str, list[Callable]]

def subscribe(event: str, handler: Callable) -> None: ...
def emit(event: str, *args: object) -> None:
    """逐个调用订阅者；单个订阅者异常捕获并 error 日志，绝不影响主流程（事务已完成）。"""

# 事件名常量与载荷（b2be 在下述时点 emit；b2be 未订阅时安全 no-op）：
PRODUCT_PUBLISHED      = "product.published"        # (product)              发布 commit 后
PRODUCT_UPDATED        = "product.updated"          # (product, changed: set[str])  编辑 commit 后
PRODUCT_DELETED        = "product.deleted"          # (product_id: int)      删除 commit 后
PRODUCT_STATUS_CHANGED = "product.status_changed"   # (product, old_status: str)   上下架 commit 后
PRODUCT_VIEWED         = "product.viewed"           # (user_id: int, product)      详情 200 组装前
FAVORITE_CHANGED       = "favorite.changed"         # (user_id: int, product, favorited: bool)
```

`changed` 为本次编辑实际变化的字段名集合（比对请求与原值；`image_ids` 变化不进该集合——向量订阅方不关心图片）。b2be2 依此判断：模板字段（`title/description/category_id/condition`）∈ changed → 重建向量；仅 `price/campus_id` 变 → 只更新 Chroma metadata。

2. **模型形态**：`Product` 含 `to_summary_dict()` / `to_detail_dict()`（含图集 `images: list[dict]`）纯序列化方法，供响应组装与缓存序列化复用；序列化输出与契约 `ProductSummary`/`ProductDetail` 逐字段一致（含 `cover`=首图、`seller`=UserSummary、`category`=CategoryRef、`campus`=CampusRef nullable）。
3. **服务函数签名**（b2be2 的 search/recommendation 直接调用）：

```python
# product_service.py
def get_on_sale_by_ids(school_id: int | None, ids: list[int], *, scope_all: bool = False) -> list[Product]
    # 按传入 id 顺序返回本校（或 scope_all 全部）在售商品；供向量召回后精筛
def list_on_sale_random(school_id: int | None, exclude_ids: list[int], limit: int, *, scope_all: bool = False) -> list[Product]
    # 随机补足（MySQL ORDER BY RAND() 或 id 池抽样，量小可用 RAND）
def get_active_by_id(product_id: int) -> Product | None   # 任意非 deleted 商品（含本校校验由调用方 scope 决定）
```

### 1. `src/model.py` 追加四模型（含迁移）

- 迁移一个版本脚本（4 表 + 索引），**FK 约束名经 `prefix()` 参数化常量单一来源**（b1 教训：模型与迁移建/删三处统一引用）；worktree MySQL 实测 `upgrade`/`downgrade` 各一次；成环 FK 不存在（本批新表只引用 b1 旧表）。
- 校验写入模型约束（`CheckConstraint('price >= 0.01 AND price <= 99999.99')` 一类仅作兜底，**业务校验在 service**，模型层不抛业务码）。

| 文件 | 函数（错误码经 `ApiError` 抛出） |
| --- | --- |

## 🔍 审查重点（审查 agent 附加对照）

1. **防探测一致性**：非本人/他校/不存在一律 404/9002，任何接口不得区分三种情况；`mine`/`favorites/mine` 例外（本人数据，无探测面）。
2. **事务边界**：发布 = products + product_images 同一事务；收藏 = favorite + favorite_count 原子更新同一事务；emit 一律在 commit 之后。
3. **缓存正确性**：detail 缓存不含 `is_favorited`/`view_count`（因人而异/每次变更）；编辑/状态/删除后失效；键含 school_id。
4. **并发边界**：重复收藏靠 `uk_user_product` 兜底（IntegrityError → 9003 非 500）；favorite_count 用 SQL 原子自增非读改写。
5. **金额纪律**：price 全链路 Decimal（ORM DECIMAL(10,2)），序列化两位小数字符串化输出与契约 number 一致；无 float 比较。
6. **图片 Cookie 安全**：httpOnly/SameSite=Lax/path=/api/images 四属性齐全；Cookie 走同一黑名单；非图片路由不接受 Cookie（CSRF 面不扩大）。
7. **事件签名**：对照本卡 Interfaces 节逐字核对（b2be2 将按此实现，漂移即阻断）。
8. **b1 存量微改范围**：auth/images/app 改动仅限任务卡所列三处，无顺手重构。
