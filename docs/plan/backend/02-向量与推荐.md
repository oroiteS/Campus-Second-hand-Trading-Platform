## 🎯 目标与范围

在 b2be 已并入 `integration/b2-product` 的基线上，实现契约 0.3.0 的**向量侧 2 个接口**（搜索 + 首页推荐），落地 MongoDB/Chroma/Embedding 三客户端、发布链路向量同步（订阅 b2be 事件总线）、行为画像（点击/收藏）、降级矩阵与 60s 补偿线程。四存储全部投产，本任务是「反目标」四条中**推荐与搜索两条**的正面交付。

**做**：`GET /api/products/search`、`GET /api/recommendations/home`、`common/mongo_client.py`、`common/chroma_client.py`、`common/embedding_client.py`、`vector_service` / `behavior_service` / `search_service` / `recommendation_service` / `events_subscribers`、向量重试 worker、`.env.example` 补 `VECTOR_RETRY_WORKER`。
**不做**：MySQL 侧任何模型/迁移/路由改动（模型与服务签名以 b2be 交付为准）、购买行为画像（b3 订单接入时订阅扩展）、敏感词（b5）、b0 health 探活重构（见决策：探活与业务客户端并存）。

### 涉及 FR / NFR / AC

FR-GDS-05（向量搜索）/ FR-GDS-06（首页推荐）/ FR-GDS-02（编辑重建向量）· NFR-01（推荐 P95<1.5s）/ NFR-04（搜索 P95<500ms）/ NFR-11（降级可演示）· AC-07（配比）/ AC-08（画像）/ AC-09（语义召回）/ AC-17/18（降级与双模）。

## 📁 交付物清单（精确文件）

### 1. `src/common/` 三客户端（横切，不含业务；批次计划决策点 11 已确认扩充）

| 文件 | 职责（签名级约定） |
| --- | --- |
| `mongo_client.py` | 懒初始化 `get_db() -> Database`（`MONGO_URI` + `MONGO_DB`，`serverSelectionTimeoutMS=2000`）；仅本模块 import pymongo |
| `chroma_client.py` | 懒初始化 `get_collection() -> Collection`（HttpClient 连 `CHROMA_HOST/PORT`；`get_or_create_collection(name="product_vectors" + CHROMA_COLLECTION_SUFFIX, metadata={"hnsw:space": "cosine"})`）；`delete_collection()`（收尾清理与重建用）；仅本模块 import chromadb |
| `embedding_client.py` | `embed_texts(texts: list[str]) -> list[list[float]]`（OpenAI 兼容 `/v1/embeddings`，按 `EMBEDDING_MODE` local/cloud/auto 选端点，批量上限 32/次自动分批，超时 10s 重试 1 次）；`is_available() -> tuple[bool, str]`（快速探测，供降级判定）；**b0 health 探活（system_service）不迁移不重构**——探活是「单条真实请求」语义、业务是「批量+降级」语义，短期两形态并存，取舍注明于模块 docstring |

模型/维度一致性：`EMBEDDING_MODEL`/`EMBEDDING_DIM`（1024）写入 Mongo 文档与 Chroma metadata 校验；维度不符 → 拒写 + error 日志（需求：切模型须重建，不得混维）。

### 2. `src/services/` 四件 + 订阅接线

| 文件 | 函数与规则 |
| --- | --- |
| `vector_service.py` | `build_text(product, category_name) -> str`（固定模板四行：标题/分类/成色/描述，照需求原文）；`text_hash(text) -> str`；`sync_product(product) -> None`（流程：模板文本 → `text_hash` 与 Mongo 存量比对，**未变且 metadata 未变则跳过** → `embed_texts([text])` → Mongo `product_vectors` upsert（`product_id` 唯一，含 vector/dim/model/text_hash/school_id/status/updated_at）→ Chroma upsert（id=str(product_id)，embedding，document=模板文本，metadata={school_id, campus_id, category_id, price, status, seller_id}）；**任一步失败 → Redis `queue:vector:retry`（系统库 offset=3）RPUSH JSON {product_id, ts} + error 日志，发布主流程不受影响**——事件订阅内已隔离异常）；`update_status_metadata(product)`（仅状态/价格变：Chroma metadata 局部 update + Mongo 同步，不重算向量）；`remove_product(product_id)`（Mongo delete + Chroma delete）；`rebuild_all()` |
| `behavior_service.py` | `record_view(user_id, product)` / `record_favorite(user_id, product, favorited)`：① `user_behaviors` 流水 insert（action=view/favorite、weight 对应 0.82/0.70、school_id、source、created_at）——**流水无条件记录**；② 画像更新：**同一 (user_id, product_id, action) 24h 内第二次起跳过**（流水仍记，照需求）；③ 取商品向量（Mongo 无则现场 `embed_texts`，失败则本次画像更新跳过进重试）；④ 更新公式 `new = product_vec × (1-w) + old × w`，无画像时 `new = product_vec`；⑤ **L2 归一化**后 upsert `user_profiles`（user_id 唯一，vector/dim/model/behavior_count+1/updated_at）。购买行为（w=0.55）本批不接，b3 订阅扩展 |
| `search_service.py` | `search(user, q, filters, page, page_size) -> dict`：`q` 拼检索指令前缀（`EMBEDDING_QUERY_PREFIX` 配置，默认 Qwen3 检索指令）→ `embed_texts` → Chroma `query(query_embeddings, n_results=90, where={"$and":[{"school_id": g.school_id},{"status":"on_sale"}]})` → 得 (id, distance) 列表 → `product_service.get_on_sale_by_ids` 精筛业务条件（分类/价格/成色/校区）→ 保序（按相似度）分页。**降级**（embedding 或 chroma 不可用，`is_available`+异常双判定）：MySQL `LIKE %q%` 标题（created_at 倒序），响应附加 `degraded: true, degraded_reason`，info 日志。结果不写缓存 |
| `recommendation_service.py` | `home_feed(user, refresh=False) -> dict`：`refresh` 或未命中缓存时计算——① 查 `user_profiles`：无文档（冷启动）→ `list_on_sale_random(school_id, exclude=[], limit=40)` 全随机；② 有画像 → Chroma `query(user_vector, n_results=90, where 本校+on_sale)` 召回 → **过滤：自己发布（seller_id）、非 on_sale（保底再滤）、批内 id 去重** → 取前 32；③ `list_on_sale_random(school_id, exclude_ids=已选, limit=40-len)` 补足缺口（含随机 8 池）→ 合并 40（不足即实际数）；④ 写缓存 `product:home:{school}:{user}` TTL 300s（`scoped_key`，商品库 offset=2）。**降级**：embedding/chroma/mongo 任一不可用 → 全随机 + `degraded: true` + reason（Redis 不可用 → 跳过缓存直算，**不算 degraded**）。管理员 → `{"items": []}`（无推荐语义） |
| `events_subscribers.py` | `register_all()`：`PRODUCT_PUBLISHED → vector_service.sync_product`；`PRODUCT_UPDATED → changed 含模板字段(title/description/category_id/condition) 则 sync_product，否则(仅 price/campus_id) update_status_metadata`；`PRODUCT_DELETED / PRODUCT_STATUS_CHANGED → remove_product / update_status_metadata`；`PRODUCT_VIEWED → behavior_service.record_view`；`FAVORITE_CHANGED → record_favorite`。由 `router.py` 末尾 import 接线（幂等：重复调用不重复注册） |

### 3. `src/routes/` 两件 + 注册 + worker

- `search.py`（`bp`，`GET /api/products/search`，与 `products.py` 同 url_prefix 不同 endpoint 无冲突）、`recommendations.py`（`GET /api/recommendations/home`）；`router.py` 追加注册 + `events_subscribers.register_all()` 一行。
- `vector_retry_worker.py`（`src/services/` 或独立模块，遵循分层放 services）：daemon 线程每 60s `LPOP` 批量重放 `queue:vector:retry`（单条重试失败且超 24h 丢弃 + error 日志防死信堆积）；`create_app()` 内按 `VECTOR_RETRY_WORKER`（默认 `1`）决定是否启动——**app.py 仅加 3 行**（读配置、条件启动），其余逻辑在 worker 模块；`.env.example` 追加一行注释完备的开关。
- Mongo 索引启动幂等：`ensure_indexes()`（`user_profiles.user_id` 唯一、`product_vectors.product_id` 唯一、`user_behaviors` 的 `(user_id, created_at)` 与 `product_id`），随 `register_all` 执行。

## 🔍 审查重点（审查 agent 附加对照）

1. **同校隔离的向量面**：Chroma where 必须 `school_id` + `status=on_sale` 双条件（防跨校召回与已售泄漏）；随机补足走 `scoped_query` 路径。
2. **「随机冒充推荐」反目标**：有画像用户的推荐必须经过画像向量召回（代码路径可追溯），降级全随机必须带 degraded 标记（AC-17 的诚实性）。
3. **事务与最终一致**：事件在 commit 后 emit（b2be 保证，本任务核对接线）；向量写失败绝不影响发布/编辑/收藏的 200 响应；重试队列不丢消息（LPUSH/RPOP 原子）。
4. **性能口径**：embed_texts 批量分批（发布单条、重建批量）；推荐接口整体不超 NFR-01 预算（桩测试无法证实时，审查核对代码路径无同步长阻塞——worker/降级路径齐全）。
5. **桩的忠实度**：fake_chroma 距离计算与真实余弦同构（审查抽验一个已知向量例）；fake_embedding 确定性（同文本同向量）。
6. **b2be 零侵入**：git diff 验证（见验收末条），越界即阻断。
7. **配置面**：`EMBEDDING_QUERY_PREFIX`、`VECTOR_RETRY_WORKER` 入 `.env.example` 与 `config.py`（唯一读 env 处）；worktree 隔离参数正确。
