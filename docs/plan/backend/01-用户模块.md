# b1 后端任务 · 用户模块

_版本 v1.0 · 2026-10-20 · 任务代号 `b1be` · 分支 `feat/be/b1-user` · worktree `.worktree/b1be` · 槽位 A（端口 5010 · Redis 基址 4 · 表前缀 `b1be-`）· 批次计划：[01-用户域](01-用户域.md)_

---

## 🎯 目标与范围

在 b0 骨架上实现契约 0.2.0 的**全部 12 个用户域接口**，并落地两项跨批次地基：JWT 鉴权三装饰器与同校作用域上下文、图片表与鉴权访问路由。

**做**：`auth`（注册/登录/登出/重置）、`users`（资料/改密/头像）、`certification`（提交/历史）、`schools`（公开列表）、`images`（鉴权访问）、20xx 错误码、五表迁移、pytest 全覆盖。
**不做**：管理端审核与学校维护（b5）、商品域接口（b2）、用户主页 `GET /users/{id}`（b3）、种子数据脚本（b6）。

### 涉及 FR / NFR

FR-USR-01 ~ 10（11 除外）· NFR-05（bcrypt）· NFR-06（JWT + 角色）· NFR-07/08（上传四件套、学生证访问控制）· NFR-09（ORM 参数化）· NFR-13（配置外置）· NFR-14（结构化日志）。

### 1. `src/model.py` 追加五模型（含迁移）

| 模型 | 表（prefix 包裹） | 关键列与索引 |
| --- | --- | --- |
| `User` | `b1be-users` | `username`(uk_username 唯一)、`student_no`(uk_student_no 唯一)、`password_hash`、`email`、`nickname`、`display_name`、`phone`(nullable，**1 开头 11 位纯数字 `^1\d{10}$`，空串 = 清除存 NULL**)、`school_id`(FK nullable)、`campus_id`(FK nullable)、`avatar_image_id`(FK nullable)、`role`、`auth_status`、`status`、`credit_score`(nullable)、`created_at`；复合索引 `idx_school_auth(school_id, auth_status)` |
| `School` | `b1be-schools` | `name`(唯一)、`multi_campus`(bool)、`status`(enabled/disabled)、`created_at` |
| `Campus` | `b1be-campuses` | `school_id`(FK)、`name`、`status`；索引 `idx_school` |
| `AuthApplication` | `b1be-auth_applications` | `user_id`、`school_id`、`campus_id`(nullable)、`student_no`、`real_name`、`student_card_image_id`(FK)、`status`(pending/approved/rejected)、`reject_reason`(nullable)、`reviewer_id`(nullable)、`reviewed_at`(nullable)、`created_at`；索引 `idx_user_status(user_id, status)` |
| `Image` | `b1be-images` | `owner_id`(FK)、`path`(相对路径)、`mime`、`size_bytes`、`sha256`、`purpose`(avatar/student_card)、`created_at` |

- `phone` 列为对需求 ER 图的补充（ER 漏列，FR-USR-04 为准，批次计划决策点 3）。
- 模型仅放单行数据行为（如 `User.display_name_recalc(school, campus)` 一类纯计算）；跨行业务全部在 service。
- 迁移：`flask db migrate -m "b1 user domain tables"` **一个版本脚本**含 5 表 + 全部索引；worktree MySQL 上实测 `upgrade` 与 `downgrade` 各一次。测试环境（SQLite 内存）用 `db.create_all()`，不跑 Alembic。

### 2. `src/common/` 增量四件（横切，不含业务）

| 文件 | 职责（签名级约定） |
| --- | --- |
| `auth.py` | `@login_required`（JWT 有效 → `g.current_user`）、`@verified_required`（`auth_status == approved` 且为学生，或管理员）、`@admin_required`（`role == admin`，否则 403/1005）；`inject_scope()`：请求进入即注入 `g.school_id`（学生）/ `g.scope_all = True`（管理员）；`register_jwt_hooks(jwt)`：`token_in_blocklist_loader` 查 Redis 黑名单（**Redis 故障 fail-open 放行 + 日志告警**，与降级决策一致）。权限判定一律查库实时状态，令牌 claims 不做判权依据 |
| `security.py` | `hash_password(raw) -> str`、`verify_password(raw, hashed) -> bool`（bcrypt）；`issue_token(user) -> tuple[str, int]`（flask-jwt-extended，identity = `str(user.id)`，返回 token 与 expires_in 秒） |
| `uploads.py` | `validate_and_save(file_storage, purpose) -> Image`：四件套校验（扩展名 jpg/png/webp + MIME + ≤5MB + 内容 sha256 改名），落 `UPLOAD_DIR/<purpose>/<年月>/`，写 images 表由 service 提交 |
| `redis_client.py` | 懒初始化单例 `get_redis() -> Redis`（db = `REDIS_DB_BASE + 3` 系统库）；仅本模块 import redis |

> 鉴权装饰器与作用域属规范既定 common 职责；`redis_client.py` 为新增横切件，已经批次计划决策点 2 报请确认。

### 3. `src/services/` 五件（业务 + 事务边界）

| 文件 | 函数（输入 → 输出，错误码经 `ApiError` 抛出） |
| --- | --- |
| `auth_service.py` | `register(payload) -> User`（唯一性 2001/2002；bcrypt 落库）；`login(account, password, client_ip) -> tuple[User, str, int]`（先用户名后学号；banned → 2006；失败计数 `rate:login:{client_ip}` 5 次 → 429/1006，成功清零；**Redis 故障时限流放行 + 告警日志**）；`logout(jti, remaining_seconds) -> dict`（写黑名单，Redis 故障返回 `{"degraded": True, "degraded_reason": ...}`）；`reset_password(payload) -> None`（凭证不匹配或用户名不存在一律 2004） |
| `user_service.py` | `get_profile(user_id) -> User`；`update_profile(user, payload) -> User`（仅更新出现字段；字段规则按批次计划「3.0 字段校验对照表」**在 service 独立复验，不信任客户端**——`phone` 须匹配 `^1\d{10}$`、空串清除存 NULL；approved 且 nickname 变更 → `display_name` 重算）；`change_password(user, old, new) -> None`（2003；新密码规则同注册）；`update_avatar(user, image) -> User` |
| `certification_service.py` | `submit(user, form, image) -> AuthApplication`（学生 + `auth_status ∈ {unverified, rejected}` 否则 9003；学号一致性/校区必选/学校启用 → 9001；提交后用户 → pending）；`my_applications(user_id) -> list[AuthApplication]`（created_at 倒序） |
| `school_service.py` | `list_enabled() -> list[School]`（含 campuses，按名称排序） |
| `image_service.py` | `get_with_access_check(image_id, current_user) -> Image`（`student_card` 仅本人与管理员，越权 404/9002）；文件读取助手 `open_file(image) -> Path` |

`display_name` 生成规则单处实现（`昵称-学校名称[校区名称]`），认证通过重算入口留给 b5 审核服务调用，本批次以 approved 造数数据经测试覆盖。

## 🔍 审查重点（审查 agent 附加对照）

1. **令牌与状态时点**：权限判定查库而非信 claims；登出后 `jti` 拒绝；过期 1002 与注销 1003 区分正确。
2. **防探测语义**：登录失败不区分"用户名不存在/密码错误"（同 2005）；重置同理（2004）；学生证越权与不存在同 404。
3. **限流正确性**：计数键按 IP、TTL 600s、阈值 5、成功清零；`1006` 与通用 `9006` 不混用。
4. **并发边界**：注册唯一性依赖数据库唯一约束兜底（竞态下 IntegrityError → 2001/2002，而非 500）。
5. **事务边界**：认证提交 = 申请记录 + 用户状态 pending + 图片记录，同一事务 commit；部分失败全回滚。
6. **字段校验双保险**：对照批次计划「3.0 字段校验对照表」逐字段核对——后端必须在 routes/service 独立复验（绕过前端直接 curl 也被 9001 拦截）；重点抽查 `phone`（`^1\d{10}$`、空串清除）、`password`（字母+数字）、`username` pattern。
7. **密码存储纪律**：注册、改密、重置三条链路落库均为 bcrypt 加盐哈希；任何日志、响应、异常信息中不得出现明文密码或可逆形式。
